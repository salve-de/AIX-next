# Rovan 継続価値・リテンション設計

> 月額Watchでユーザーが継続して受け取る価値を定義する正本。実装・本番稼働の成立は別途検証する。
>
> 最終更新: 2026-09-09

## 0. 結論

月額で売るものは「毎週レポートを読む権利」でも「毎週サイトを直す宿題」でもない。

**RovanがAI上の購買リスクを継続監視し、重要な変化が起きた時だけユーザーが分かる状態**を提供する。

監視対象:

- 重要な購入前質問での新しい候補落ち
- 候補入り回復
- AI回答と公式情報の新しい明確な食い違い
- 新しい競合候補
- 新しい外部Citationドメイン
- 取得失敗・比較条件不一致等の測定異常

平常時は「異常なし」でよい。価値は毎週新しい施策を作ることではなく、知らない間にAI上の扱われ方が悪化する状態を見逃さないことにある。

## 1. ユーザーが継続課金する理由

### 安心

自社でChatGPT・Gemini・Perplexityを毎週確認しなくても、指定条件の観測をRovanが継続する。

### 発見

前回は問題がなかった重要質問で候補外になった、新しい競合が出た、AIが料金等を誤って説明し始めた、といった変化を発見する。

### 解決

問題が確認された時は、Change Packで対象ページ、見出し、本文、FAQ、根拠を整理する。平常時に変更を乱発しない。

### 検証

修正後は同じ測定条件で再観測し、候補状態や回答がどう変化したかを記録する。ただし前後差から因果効果を断定しない。

## 2. Watchの基本ループ

```text
Baseline
→ 定期観測
→ 重要変化を検出
→ 必要な時だけ通知
→ 必要な時だけChange Pack
→ 実装後に再測定
→ 次の監視へ
```

## 3. 異常イベント

比較条件が一致する場合に、次を前回との差分として扱う。

| event | 条件 | ユーザーへの意味 |
| --- | --- | --- |
| candidate_drop | 前回50%以上候補入り → 今回50%未満 | 重要質問で候補外が増えた |
| candidate_recovery | 前回50%未満 → 今回50%以上 | 候補入りが回復した |
| new_fact_error | 前回になかった明確なAI-vs公式矛盾 | AIの説明に新しい食い違い |
| new_competitor | 前回になかった競合候補 | 比較候補の顔ぶれが変わった |
| citation_change | 重要質問で新しい外部Citationドメイン | AIが使う外部情報源が変わった |

パネル、Provider、地域等が比較不能な場合は、前後差を異常として断定しない。

## 4. 通知設計

通知は「何か変わった」ことを中心にする。

例:

```text
今週の重要変化
- 新たな候補落ち: 2件
- 新しいAI誤情報: 1件
- 新しい競合: 1社
```

通知には具体的な質問や食い違いを含めるが、実顧客の流出件数や売上損失へ換算しない。

異常がない週に、利用者へ修正作業を要求しない。

## 5. Fact Accuracyの継続監視

誤情報として扱うのは、次が揃った場合だけ。

- AI回答本文に対象主張が存在する
- 公式サイト取得本文に直接矛盾する事実が存在する
- 公式URLが取得済み対象ページである

公式サイトに情報がない、表現が曖昧、両立可能な場合は誤情報としない。

対象例:

- 料金
- 利用条件
- 対応範囲
- 中核機能
- 連携
- 無料体験
- 対応地域
- サポート
- セキュリティ

## 6. 購入前質問の扱い

固定コアパネルを保持しつつ、Watch画面では比較・価格・用途・機能・対象顧客等の商用意図が強い質問を優先して見せる。

この優先度は実際の検索ボリューム、購入確率、売上額ではない。Rovan内部の確認優先度である。

## 7. Change Packの役割

Change Packはリテンションのために毎週量産するコンテンツではない。

次のような具体的問題が見つかった時の解決手段として使う。

- 公式サイトに実在する重要条件が分かりにくい
- AI回答で繰り返し候補外になる質問に関係する情報不足がある
- AIの誤情報の原因となり得る古い/曖昧な公式表現が確認できる

未確認の事実を創作しない。顧客サイトへ自動公開しない。

## 8. 公開プロフィール等の補助機能

Rovan-hosted公開プロフィール、JSON-LD、`llms.txt`下書きは継続課金の本体にしない。

これらは実験・補助機能として残し、実際にCitationや候補状態に関係したかを観測する。効果が証明される前に「公開しておけば推薦される」と売らない。

## 9. 継続測定の最低表示項目

- 質問パネル種別・バージョン
- Provider / モデル
- 測定日時
- 予定観測数 / 成功数 / 未取得数
- 重要質問の候補入り状態
- AI-vs公式の明確な事実不一致
- 競合候補
- Citation
- 前回との差分
- 比較可能かどうか

取得失敗を候補外として数えない。

## 10. 価格検証

現行検証価格は **月額19,800円（税込）**。

この価格で継続価値が成立するかは、実ユーザーの課金・継続率で判断する。機能数が多いことを価格根拠にしない。

本番公開前にStripeの実Priceと表示価格が一致していることを確認する。

## 11. 解約を防ぐ方法

解約困難化や過剰な通知ではなく、次で継続理由を作る。

- 設定後の作業負荷が低い
- 重要な変化だけが分かる
- 変化の根拠へすぐ降りられる
- 問題時に解決案がある
- 履歴が蓄積し、前回との比較価値が増える

「何も起きなかった週」に架空の成果を作らない。

## 12. Truth boundary

- Watchは全AI利用者の会話を監視するものではない。
- 候補外は実顧客流出ではない。
- AI誤情報は公式情報との直接矛盾がある場合だけ扱う。
- 外部Citationは危険・権威を意味しない。
- 前後差は因果効果の証明ではない。
- 推薦、Citation、問い合わせ、契約、売上は保証しない。
- 顧客サイトを無断変更しない。
