# Rovan 中核プロダクト戦略

> Rovanの現行製品目標・提供価値・測定境界をまとめる正本。実装・本番稼働の成立は別途検証する。
>
> 最終更新: 2026-09-09

## 0. 結論

Rovanは、**AIが購買前の利用者に対して対象企業をどう選び、どう説明しているかを監視する「AI購買監査」サービス**である。

主価値は「LLMOスコア」や「AI順位」ではない。

1. 購入判断に近い質問で自社が候補から落ちている場面を発見する。
2. AI回答と公式サイト本文に明確な矛盾がある場合だけ、AI誤情報として発見する。
3. 新しい競合、候補落ち、候補回復、外部参照元の変化を継続監視する。
4. 問題がある時だけ、対象ページ・見出し・本文・FAQ・根拠を含むChange Packを作る。

```text
会社名 / URL
→ 対象サイト確認
→ 会社・市場・競合の理解
→ 購入判断に近いBuyer Promptを優先
→ OpenAI / Gemini / Perplexityを観測
→ 候補落ち / 競合 / Citation
→ AI回答と公式サイトの明確な事実矛盾を照合
→ Watchで前回からの重要変化を監視
→ 問題があればChange Pack
→ 同条件で再測定
```

利用者に毎週宿題を出すことを継続価値にしない。平常時は作業不要で、重要な変化が起きた時に確認できる状態を月額商品の中心にする。

## 1. 顧客が受け取る価値

### 1.1 候補落ちが分かる

「おすすめは？」「AとBなら？」「中小企業向けは？」「この条件なら？」のような購入前質問で、対象企業が回答候補に入ったかを観測する。

候補外は実際の顧客流出を意味しない。Rovanが指定条件で観測した回答上の状態である。

### 1.2 AIの説明が公式情報と食い違っていないか分かる

対象例:

- 料金
- 利用条件
- 対象顧客
- 中核機能
- 外部連携
- 無料体験
- 対応地域
- サポート条件
- セキュリティ条件

公式サイトに記載がないだけでは誤情報としない。AI回答本文の短い事実表現と、対象企業の公式サイト本文の短い事実表現が直接矛盾する場合だけ確認対象とする。

### 1.3 競合と参照元の変化が分かる

重要な購入前質問で、新しい競合候補や新しい外部Citationドメインが現れた場合に前回との差分として残す。

### 1.4 問題があれば直し方まで分かる

Change Packは次を人間確認用に出す。

- 対象ページ
- 変更目的
- 新しいタイトル・見出し
- リード・本文
- FAQ
- 使用した事実
- 参照元URL
- 関係するBuyer Prompt
- 公開前チェック

顧客サイトへ自動で書き込まない。

## 2. 入力と観測

### 2.1 入力

最初は会社名、商品名、サービス名、またはURL一つで開始できる。名前入力時は検索で見つかった対象サイト候補を利用者が確認してから測定する。同名企業を自動確定しない。

### 2.2 購入意図の優先

全Buyer Promptを同じ重さで見せない。比較、価格、代替、機能、用途、対象顧客、導入条件など、購入判断に近い質問を相対的に優先する。

この優先度は検索ボリューム・購入確率・売上予測ではなく、Rovan内部の監査優先度である。

### 2.3 AI観測

指定Providerで同じ質問を実行し、回答本文、候補文字列、Citation、Provider、モデル、日時、成功・失敗状態を保存する。

OpenAI面を含む観測はRovanの統一条件によるAPI観測であり、Consumer版UIの全ユーザー会話を取得したものではない。

## 3. AI購買監査

### 3.1 候補落ち

重要質問ごとに、取得成功した回答のうち自社が候補に含まれた割合を計算する。Provider別にも候補外が優勢かを見る。

取得失敗は候補外として数えない。

### 3.2 Fact Accuracy

AI誤情報の判定は保守的に行う。

- AI回答に対象主張が実際に存在する。
- 公式サイトの取得本文に対立する事実が実際に存在する。
- 公式URLがRovanの取得済み許可リストに含まれる。
- 両者が直接矛盾する。

AIに「正解」を推測させない。会社サイトに情報がない、表現が曖昧、意味が両立可能な場合は誤情報としない。

### 3.3 Citation

重要質問でAIが引用したURL・ドメインを対象企業ドメインと外部ドメインに分ける。外部ドメインであること自体を危険とは扱わない。新しい参照元が現れた場合や、誤情報と結びついた場合に確認材料とする。

## 4. Watch

月額商品の中心は「毎週新しい改善案を作ること」ではなく、**重要な異常を継続監視すること**。

比較可能な同じ測定条件で、次を差分イベントとして扱う。

- `candidate_drop`: 前回50%以上候補入り → 今回50%未満
- `candidate_recovery`: 前回50%未満 → 今回50%以上
- `new_fact_error`: 前回になかった明確なFact Accuracy Issue
- `new_competitor`: 前回になかった競合候補
- `citation_change`: 重要質問で新しい外部Citationドメイン

測定条件が一致しない場合は、候補落ち・新競合・Citation変化を同一条件の前後差として断定しない。

通知は重要な変化がある時を中心にする。平常時は利用者へ作業を強要しない。

## 5. 測定指標

従来の指標は補助として残す。

- 候補入り率
- 第一候補率
- Mention Coverage
- Citation Coverage
- Repeat Agreement
- Measurement Completeness

固定コアパネルの候補入り率も内部・詳細画面では保持できるが、商品トップの主語は「AI顧客奪還シェア」ではなく、候補落ち・誤情報・競合/参照元の重要変化とする。

無料診断と有料Watchのパネルは区別する。欠損時は成功分母・予定数・未取得数を示す。

## 6. 公開情報参照ページ・AI-readable

Rovan-hosted公開情報参照ページ、JSON-LD、Markdown、`llms.txt`下書きは補助機能・実験対象として残す。

これらについて、以下を主張しない。

- 公開すればAI推薦が改善する
- AIが常時参照する
- AI事業者公認データである
- 検索順位・Citation・問い合わせが増えることを保証する

公開ページは対象会社サイトへの書き込みではない。明示同意、停止、訂正、非公開、参照元、内部データ分離の既存安全境界を維持する。

## 7. 顧客サイトへの変更

初期商品の利用条件として以下を要求しない。

- GitHub
- WordPress管理者権限
- FTP
- CMS管理者権限

Rovanは診断・監視・Change Pack生成をサイト権限なしで成立させる。将来CMS DraftやPR連携を追加する場合も、最小権限・人間確認・ロールバックを前提とし、無断公開を行わない。

## 8. 画面の優先順位

結果画面の優先順位:

1. 重要質問で候補外になっている件数
2. 公式情報との明確な食い違い
3. 重要質問で使われた外部情報源
4. 今確認すべきアラート
5. 個別の購入前質問・競合・Provider
6. 詳細Citation
7. Evidence / Change Pack / 技術監査等の補助情報

Watch画面では、前回からの新しい異常を最初に見せる。

## 9. 料金

検証価格は **月額19,800円（税込）**。

- 無料診断: ¥0
- Watch: ¥19,800/月（税込）

本番では `STRIPE_PRICE_ID` が同じ金額のStripe Priceを参照することを確認する。コード上の表示価格変更だけではStripe請求額は変わらない。

## 10. データの出所と境界

| データ | 出所 | 表示 |
| --- | --- | --- |
| 会社名・市場・用途 | 対象サイト・検索で確認した公開情報 | 対象確認付き |
| AI回答・候補 | 指定Providerへの質問 | 観測ログとして扱う |
| Citation | AI回答から取得したURL | 質問との対応を表示 |
| Fact Accuracy | AI回答原文 + 公式サイト原文 | 両方が直接矛盾する場合だけ表示 |
| Change Pack | 公開事実・会社確認済み事実・測定結果 | 人間確認用下書き |
| Watch差分 | 比較可能な保存済み測定 | 条件一致時のみ前後差扱い |
| サンプル | 固定の架空fixture | サンプル・noindexを明示 |

## 11. 法務・編集上の境界

1. AI内部ランキングを取得したと表現しない。
2. 候補外を実顧客流出と表現しない。
3. AI回答の一時的な前後差から因果効果を断定しない。
4. 公式サイトに書かれていないだけで誤情報と断定しない。
5. 他社の文章・画像・評価をコピーしない。
6. 本人確認や公的認証をしていないページを「公式」「公認」と呼ばない。
7. AIの推薦、引用、掲載順位、流入、問い合わせ、契約、売上を保証しない。
8. 医療、金融、法務等の高リスク判断を自動代替しない。

## 12. 実装済み範囲

- URL・社名入力と対象確認
- 公開サイト取得、robots、SSRF対策
- OpenAI / Gemini / Perplexity観測
- Buyer Prompt生成
- 購入意図の相対優先
- 重要質問の候補落ち集計
- 外部Citationドメイン集計
- AI回答と公式サイトの保守的Fact Accuracy照合
- Watchの候補落ち/回復、新競合、新Fact Error、新Citationドメイン差分
- 結果画面のAI購買監査パネル
- Watch公開DTOへの監査結果保持
- 重要異常メール
- Change Pack
- Stripe Subscriptionフロー
- Supabase永続化経路
- 公開プロフィール等の補助機能

本番Provider設定、Stripe Price、DB migration、メール設定、実AI E2Eはリポジトリ内コードが存在することとは別に確認する。

## 13. 受け入れ条件

実装完了を主張するには、少なくとも一つの実URLで次を確認する。

1. 対象会社を正しく確定できる。
2. 購入判断に近い質問を生成・優先できる。
3. AI回答の成功・失敗を区別できる。
4. 重要質問の自社候補入り・候補外・競合を確認できる。
5. Citation URLをたどれる。
6. 明確なAI-vs公式事実矛盾だけが誤情報として表示される。
7. 公式情報欠損を誤情報として誤検出しない。
8. 同条件再測定で新しい候補落ち・競合・誤情報等を差分化できる。
9. 条件不一致時に前後差を断定しない。
10. Change Packが許可された事実だけで作られる。
11. サンプル・実測・未確認・推定を区別できる。
12. 顧客サイトを無断変更しない。
13. 表示価格とStripe実請求価格が一致する。
